# Проектная работа "Веб-ларек"

Стек: HTML, SCSS, TS, Vite

Структура проекта:
- src/ — исходные файлы проекта
- src/components/ — папка с JS компонентами
- src/components/base/ — папка с базовым кодом
- src/components/Models/ — папка с моделями данных
- src/components/Communication/ — папка с классом для работы с сервером
- src/components/View/ — папка с компонентами представления

Важные файлы:
- index.html — HTML-файл главной страницы
- src/types/index.ts — файл с типами
- src/main.ts — точка входа приложения
- src/scss/styles.scss — корневой файл стилей
- src/utils/constants.ts — файл с константами
- src/utils/utils.ts — файл с утилитами

## Установка и запуск
Перед запуском в корне проекта нужно создать файл `.env` и указать в нём адрес сервера:

```
VITE_API_ORIGIN=https://larek-api.nomoreparties.co
```

Для установки и запуска проекта необходимо выполнить команды

```
npm install
npm run dev
```

или

```
yarn
yarn dev
```
## Сборка

```
npm run build
```

или

```
yarn build
```
# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

### Данные

В приложении используются две сущности: товар и покупатель. Все типы и интерфейсы описаны в файле `src/types/index.ts`.

#### Тип TPayment
`type TPayment = 'card' | 'cash' | ''`

Описывает способ оплаты заказа: `card` - оплата картой, `cash` - оплата при получении. Пустая строка используется как значение по умолчанию и означает, что покупатель ещё не выбрал способ оплаты.

#### Интерфейс IProduct
Описывает товар, который продаётся в магазине.

`id: string` - уникальный идентификатор товара  
`description: string` - подробное описание товара  
`image: string` - название файла с изображением товара  
`title: string` - название товара  
`category: string` - категория товара  
`price: number | null` - цена товара, у товаров без цены хранится `null`

#### Интерфейс IBuyer
Описывает данные покупателя, которые он указывает при оформлении заказа.

`payment: TPayment` - выбранный способ оплаты  
`email: string` - электронная почта покупателя  
`phone: string` - телефон покупателя  
`address: string` - адрес доставки

#### Тип TBuyerErrors
`type TBuyerErrors = Partial<Record<keyof IBuyer, string>>`

Описывает результат проверки данных покупателя. Ключ - название поля интерфейса `IBuyer`, значение - текст ошибки для этого поля. Поля, заполненные верно, в объекте отсутствуют, поэтому пустой объект означает, что все данные корректны.

#### Интерфейс IProductsResponse
Описывает объект, который приходит с сервера в ответ на запрос каталога товаров.

`total: number` - общее количество товаров на сервере  
`items: IProduct[]` - массив товаров

#### Интерфейс IOrderRequest
Описывает данные заказа, которые отправляются на сервер. Расширяет интерфейс `IBuyer`, чтобы не описывать данные покупателя второй раз.

`total: number` - итоговая сумма заказа  
`items: string[]` - массив идентификаторов купленных товаров

#### Интерфейс IOrderResponse
Описывает объект, которым сервер отвечает на оформление заказа.

`id: string` - идентификатор созданного заказа  
`total: number` - сумма, списанная за заказ

#### Типы данных слоя представления

Компоненты представления не хранят данные, но получают их в методе `render`. Для каждого компонента описан тип данных, которые он отображает.

`interface ICardEvent` - данные события, которым карточка сообщает о действии с товаром: `id: string` - идентификатор товара.

`interface IHeaderData` - данные шапки страницы: `counter: number` - количество товаров в корзине.

`interface IGalleryData` - данные каталога: `catalog: HTMLElement[]` - массив разметок карточек товара.

`interface IModalData` - данные модального окна: `content: HTMLElement` - разметка компонента, который отображается в окне.

`type TCardBase = Pick<IProduct, 'id' | 'title' | 'price'>` - данные товара, которые отображают все три вида карточек.

`type TCardCatalog = TCardBase & Pick<IProduct, 'category' | 'image'>` - данные карточки товара в каталоге.

`type TCardPreview = TCardCatalog & Pick<IProduct, 'description'> & { buttonLabel: string; buttonDisabled: boolean }` - данные подробной карточки товара. Подпись `buttonLabel` и доступность `buttonDisabled` кнопки готовит презентер, потому что они зависят от цены товара и содержимого корзины.

`type TCardBasket = TCardBase & { index: number }` - данные карточки товара в корзине, где `index` - порядковый номер товара в списке.

`interface IBasketData` - данные корзины: `items: HTMLElement[]` - массив разметок карточек товара, `total: number` - общая стоимость товаров.

`interface IFormState` - общее состояние форм: `valid: boolean` - доступность кнопки отправки, `errors: string` - текст сообщения об ошибках.

`type TOrderForm = IFormState & Pick<IBuyer, 'payment' | 'address'>` - данные формы с выбором способа оплаты и адресом доставки.

`type TContactsForm = IFormState & Pick<IBuyer, 'email' | 'phone'>` - данные формы с контактами покупателя.

`interface ISuccessData` - данные сообщения об успешном заказе: `total: number` - списанная сумма.

### Модели данных

Классы этой группы отвечают только за хранение данных и операции с ними. Они не умеют отображать данные и ничего не знают о слое представления. О каждом изменении данных модель сообщает через брокер событий, который получает в конструкторе. Классы находятся в папке `src/components/Models/`.

#### Класс Catalog
Хранит каталог товаров магазина и товар, выбранный покупателем для подробного просмотра.

Конструктор:  
`constructor(events: IEvents)` - принимает брокер событий, каталог при этом создаётся пустым.

Поля класса:  
`items: IProduct[]` - массив всех товаров магазина  
`selectedItem: IProduct | null` - товар, выбранный для подробного отображения, либо `null`, если товар не выбран  
`events: IEvents` - брокер событий, через который модель сообщает об изменении данных

Методы класса:  
`setItems(items: IProduct[]): void` - сохраняет в модели массив товаров, полученный в параметре, и генерирует событие `catalog:changed`  
`getItems(): IProduct[]` - возвращает массив всех товаров каталога  
`getItemById(id: string): IProduct | undefined` - возвращает товар с переданным идентификатором или `undefined`, если товара с таким идентификатором в каталоге нет  
`setSelectedItem(item: IProduct): void` - сохраняет товар для подробного отображения и генерирует событие `catalog:selected`  
`getSelectedItem(): IProduct | null` - возвращает товар, выбранный для подробного отображения

#### Класс Cart
Хранит товары, которые покупатель выбрал для покупки, и предоставляет данные о содержимом корзины.

Конструктор:  
`constructor(events: IEvents)` - принимает брокер событий, корзина при этом создаётся пустой.

Поля класса:  
`items: IProduct[]` - массив товаров, добавленных в корзину  
`events: IEvents` - брокер событий, через который модель сообщает об изменении данных

Методы класса:  
`getItems(): IProduct[]` - возвращает массив товаров, которые находятся в корзине  
`addItem(item: IProduct): void` - добавляет в корзину товар, полученный в параметре, и генерирует событие `cart:changed`  
`removeItem(item: IProduct): void` - удаляет из корзины товар с таким же идентификатором, как у товара из параметра, и генерирует событие `cart:changed`  
`clear(): void` - удаляет из корзины все товары и генерирует событие `cart:changed`  
`getTotalPrice(): number` - возвращает стоимость всех товаров в корзине, товары без цены считаются за ноль  
`getCount(): number` - возвращает количество товаров в корзине  
`hasItem(id: string): boolean` - проверяет, есть ли в корзине товар с переданным идентификатором

#### Класс Buyer
Хранит данные покупателя и проверяет их заполненность.

Конструктор:  
`constructor(events: IEvents)` - принимает брокер событий, все поля с данными при этом создаются пустыми.

Поля класса:  
`payment: TPayment` - выбранный способ оплаты  
`address: string` - адрес доставки  
`email: string` - электронная почта покупателя  
`phone: string` - телефон покупателя  
`events: IEvents` - брокер событий, через который модель сообщает об изменении данных

Методы класса:  
`setData(data: Partial<IBuyer>): void` - сохраняет в модели значения полей, переданных в параметре, и генерирует событие `buyer:changed`. Значения остальных полей при этом не изменяются, поэтому метод позволяет сохранить как все данные сразу, так и одно поле  
`getData(): IBuyer` - возвращает объект со всеми данными покупателя  
`clear(): void` - очищает все данные покупателя и генерирует событие `buyer:changed`  
`validate(): TBuyerErrors` - проверяет данные покупателя и возвращает объект с ошибками. Поле считается корректным, если оно не пустое

### Слой коммуникации

#### Класс ShopApi
Отвечает за обмен данными с сервером магазина: получает каталог товаров и отправляет оформленный заказ. Класс находится в папке `src/components/Communication/`. Запросы он выполняет не самостоятельно, а через объект, реализующий интерфейс `IApi`, который получает в конструкторе. Благодаря такой композиции класс не зависит от конкретной реализации клиента и не связан с моделями данных.

Конструктор:  
`constructor(api: IApi)` - принимает объект, реализующий интерфейс `IApi`, и сохраняет его в поле класса.

Поля класса:  
`api: IApi` - объект, через который выполняются запросы к серверу

Методы класса:  
`getProducts(): Promise<IProductsResponse>` - выполняет GET запрос на ендпоинт `/product/` и возвращает промис с объектом, в котором находится массив товаров  
`createOrder(order: IOrderRequest): Promise<IOrderResponse>` - выполняет POST запрос на ендпоинт `/order/`, передавая в теле запроса данные заказа из параметра, и возвращает промис с объектом, подтверждающим покупку


### Слой представления

Классы этой группы отвечают только за отображение данных на странице. Каждый класс работает со своим блоком разметки, находит все нужные DOM-элементы в конструкторе и сохраняет их в полях. Данные классы не хранят: они получают их в методе `render` и записывают в разметку через сеттеры. Логики в них нет: о действиях пользователя они сообщают событиями, а решение о том, что делать дальше, принимает презентер. Классы находятся в папке `src/components/View/`.

#### Класс Header
Отвечает за шапку страницы с кнопкой корзины и счётчиком выбранных товаров. Наследуется от `Component<IHeaderData>`.

Конструктор:  
`constructor(container: HTMLElement, events: IEvents)` - принимает элемент шапки и брокер событий, находит кнопку корзины и счётчик, вешает на кнопку слушатель клика.

Поля класса:  
`basketButton: HTMLButtonElement` - кнопка открытия корзины  
`counterElement: HTMLElement` - элемент со счётчиком товаров  
`events: IEvents` - брокер событий

Методы класса:  
`set counter(value: number)` - выводит количество товаров в корзине

#### Класс Gallery
Отвечает за каталог товаров на главной странице. Наследуется от `Component<IGalleryData>`.

Конструктор:  
`constructor(container: HTMLElement)` - принимает элемент каталога. Пользователь с самим каталогом не взаимодействует, поэтому брокер событий классу не нужен.

Методы класса:  
`set catalog(items: HTMLElement[])` - выводит в каталоге переданные разметки карточек товара

#### Класс Modal
Отвечает за модальное окно. Класс не имеет наследников: любая разметка, которая показывается в окне, это самостоятельный компонент, который передаётся в окно готовым. Наследуется от `Component<IModalData>`.

Конструктор:  
`constructor(container: HTMLElement, events: IEvents)` - принимает элемент модального окна и брокер событий, находит кнопку закрытия и контейнер содержимого, вешает слушатели клика по кнопке закрытия и по подложке окна.

Поля класса:  
`closeButton: HTMLButtonElement` - кнопка закрытия окна  
`contentElement: HTMLElement` - контейнер, в который выводится содержимое окна  
`events: IEvents` - брокер событий

Методы класса:  
`set content(value: HTMLElement)` - выводит в окне переданную разметку  
`open(): void` - показывает окно, добавляя модификатор `modal_active`  
`close(): void` - скрывает окно, убирая модификатор `modal_active`

#### Класс Card
Абстрактный класс, общий родитель всех карточек товара. Отвечает за разметку, которая есть во всех трёх шаблонах карточки: название и цену товара. Идентификатор товара карточка хранит не в поле, а в data-атрибуте своего корневого элемента, поэтому данные о товаре остаются только в модели. Наследуется от `Component<T>`, где `T` - тип данных конкретной карточки.

Конструктор:  
`protected constructor(container: HTMLElement, events: IEvents)` - принимает корневой элемент карточки и брокер событий, находит элементы названия и цены.

Поля класса:  
`titleElement: HTMLElement` - элемент с названием товара  
`priceElement: HTMLElement` - элемент с ценой товара  
`events: IEvents` - брокер событий

Методы класса:  
`set id(value: string)` - записывает идентификатор товара в data-атрибут корневого элемента  
`set title(value: string)` - выводит название товара  
`set price(value: number | null)` - выводит цену товара, для товаров без цены выводится «Бесценно»  
`emitCardEvent(eventName: string): void` - защищённый метод, генерирует событие с переданным названием и идентификатором товара, к которому относится карточка

#### Класс ProductCard
Абстрактный класс, общий родитель карточек, в разметке которых есть изображение и категория товара. Наследуется от `Card<T>`.

Конструктор:  
`protected constructor(container: HTMLElement, events: IEvents)` - принимает корневой элемент карточки и брокер событий, находит элементы категории и изображения.

Поля класса:  
`categoryElement: HTMLElement` - элемент с категорией товара  
`imageElement: HTMLImageElement` - изображение товара

Методы класса:  
`set category(value: string)` - выводит категорию товара и задаёт ей модификатор из объекта `categoryMap`  
`set image(value: string)` - выводит изображение товара, дополняя название файла адресом `CDN_URL`

#### Класс CardCatalog
Отвечает за карточку товара в каталоге, работает с шаблоном `card-catalog`. Наследуется от `ProductCard<TCardCatalog>`.

Конструктор:  
`constructor(container: HTMLElement, events: IEvents)` - принимает корневой элемент карточки и брокер событий, вешает на карточку слушатель клика, который генерирует событие `card:select`.

#### Класс CardPreview
Отвечает за подробную карточку товара, которая открывается в модальном окне, работает с шаблоном `card-preview`. Наследуется от `ProductCard<TCardPreview>`.

Конструктор:  
`constructor(container: HTMLElement, events: IEvents)` - принимает корневой элемент карточки и брокер событий, находит описание товара и кнопку, вешает на кнопку слушатель клика, который генерирует событие `card:buy`.

Поля класса:  
`descriptionElement: HTMLElement` - элемент с описанием товара  
`buyButton: HTMLButtonElement` - кнопка добавления товара в корзину и удаления из неё

Методы класса:  
`set description(value: string)` - выводит описание товара  
`set buttonLabel(value: string)` - выводит подпись кнопки  
`set buttonDisabled(value: boolean)` - блокирует или разблокирует кнопку

#### Класс CardBasket
Отвечает за карточку товара в списке корзины, работает с шаблоном `card-basket`. Наследуется от `Card<TCardBasket>`.

Конструктор:  
`constructor(container: HTMLElement, events: IEvents)` - принимает корневой элемент карточки и брокер событий, находит порядковый номер и кнопку удаления, вешает на кнопку слушатель клика, который генерирует событие `cart:remove`.

Поля класса:  
`indexElement: HTMLElement` - элемент с порядковым номером товара в списке  
`deleteButton: HTMLButtonElement` - кнопка удаления товара из корзины

Методы класса:  
`set index(value: number)` - выводит порядковый номер товара в списке

#### Класс Basket
Отвечает за корзину со списком выбранных товаров, работает с шаблоном `basket`. Наследуется от `Component<IBasketData>`.

Конструктор:  
`constructor(container: HTMLElement, events: IEvents)` - принимает корневой элемент корзины и брокер событий, находит список товаров, кнопку оформления и элемент с общей стоимостью, вешает на кнопку слушатель клика.

Поля класса:  
`listElement: HTMLElement` - список товаров корзины  
`orderButton: HTMLButtonElement` - кнопка оформления заказа  
`totalElement: HTMLElement` - элемент с общей стоимостью товаров  
`events: IEvents` - брокер событий

Методы класса:  
`set items(value: HTMLElement[])` - выводит разметки карточек товара и блокирует кнопку оформления, если список пуст. Надпись «Корзина пуста» выводится стилями для пустого списка  
`set total(value: number)` - выводит общую стоимость товаров

#### Класс Form
Абстрактный класс, общий родитель форм оформления заказа. Отвечает за отправку формы, доступность кнопки и вывод сообщения об ошибках. Названия генерируемых событий строятся из атрибута `name` формы, поэтому формы `order` и `contacts` сообщают о действиях пользователя разными событиями. Наследуется от `Component<T>`, где `T` расширяет `IFormState`.

Конструктор:  
`protected constructor(container: HTMLFormElement, events: IEvents)` - принимает элемент формы и брокер событий, сохраняет название формы, находит кнопку отправки и элемент с ошибками, вешает на форму слушатель отправки.

Поля класса:  
`submitButton: HTMLButtonElement` - кнопка отправки формы  
`errorsElement: HTMLElement` - элемент с сообщением об ошибках  
`formName: string` - название формы, из которого строятся названия её событий  
`events: IEvents` - брокер событий

Методы класса:  
`set valid(value: boolean)` - блокирует или разблокирует кнопку отправки  
`set errors(value: string)` - выводит сообщение об ошибках  
`emitChange(data: Partial<IBuyer>): void` - защищённый метод, генерирует событие об изменении данных формы

#### Класс OrderForm

Конструктор:

Поля класса:

Методы класса:

### События приложения

Все события приложения обрабатывает презентер. Модели генерируют события при изменении данных, представления генерируют события в ответ на действия пользователя.

События моделей данных:  
`catalog:changed` - в каталоге сохранён массив товаров  
`catalog:selected` - изменился товар, выбранный для подробного просмотра  
`cart:changed` - изменился состав корзины: товар добавлен, удалён или корзина очищена  
`buyer:changed` - изменились данные покупателя

События представлений:  
`card:select` - клик по карточке товара в каталоге, в событие передаётся `ICardEvent`  
`card:buy` - клик по кнопке в подробной карточке товара, в событие передаётся `ICardEvent`  
`cart:remove` - клик по кнопке удаления товара в корзине, в событие передаётся `ICardEvent`  
`basket:open` - клик по иконке корзины в шапке страницы  
`order:open` - клик по кнопке «Оформить» в корзине  
`order:change` - покупатель выбрал способ оплаты или изменил адрес доставки, в событие передаётся `Partial<IBuyer>`  
`order:submit` - отправка формы заказа кнопкой «Далее»  
`contacts:change` - покупатель изменил почту или телефон, в событие передаётся `Partial<IBuyer>`  
`contacts:submit` - отправка формы контактов кнопкой «Оплатить»  
`success:close` - клик по кнопке «За новыми покупками!»  
`modal:close` - клик по крестику модального окна или по области вне окна

### Презентер

Презентер связывает модели данных и представления и содержит всю логику приложения. Приложение состоит из одной страницы, поэтому презентер один и в отдельный класс не выносится, его код находится в файле `src/main.ts`.

Сначала в файле создаются брокер событий, модели данных, класс для работы с сервером и все компоненты представления, затем описываются обработчики событий, и в конце выполняется запрос за каталогом товаров. Презентер только обрабатывает события: сам он их не генерирует, а изменяет данные в моделях и перерисовывает представления.

Представления перерисовываются в двух случаях: при обработке события модели данных и при открытии модального окна. Данные, которые нужны представлению, презентер собирает из разных моделей сам. Например, подпись кнопки в подробной карточке зависит и от цены товара из каталога, и от содержимого корзины.

Вспомогательные функции презентера:  
`joinErrors(errors: TBuyerErrors, fields: (keyof IBuyer)[]): string` - собирает из ошибок покупателя текст для нужной формы  
`getButtonLabel(item: IProduct): string` - готовит подпись кнопки подробной карточки товара  
`renderBasket(): HTMLElement` - создаёт карточки товаров корзины и отдаёт разметку корзины с актуальным списком и стоимостью

Обработчики событий:  
`catalog:changed` - создаёт карточки для всех товаров каталога и выводит их в каталоге страницы  
`catalog:selected` - создаёт подробную карточку выбранного товара и открывает её в модальном окне  
`cart:changed` - обновляет счётчик в шапке страницы и список товаров в корзине  
`buyer:changed` - проверяет данные покупателя и обновляет состояние обеих форм заказа  
`card:select` - находит товар в каталоге и сохраняет его как выбранный для просмотра  
`card:buy` - добавляет товар в корзину или удаляет его оттуда и закрывает модальное окно  
`cart:remove` - удаляет товар из корзины  
`basket:open` - открывает корзину в модальном окне  
`order:open` - открывает форму заказа в модальном окне  
`order:change` - сохраняет способ оплаты и адрес доставки в модели покупателя  
`order:submit` - открывает форму контактов в модальном окне  
`contacts:change` - сохраняет почту и телефон в модели покупателя  
`contacts:submit` - собирает данные заказа, отправляет их на сервер, очищает корзину и данные покупателя и показывает сообщение об успешной оплате  
`success:close` - закрывает модальное окно  
`modal:close` - закрывает модальное окно
